# Outpost and memorial garden components

`createSowerOutpost({ seed })` returns a self-contained Three.js group. Its `userData` exposes `socketPositions` (three packet landing points), `meetingPositions` (three campfire seats), `sourceStations`, and a `Box3` `bounds`. Construction state is set through `setReadiness({ dispenser, computer, campfire, agents })` or an array of enabled readiness IDs. `agents` means the actual three worker slots are present. `setPhase('work'|'review'|'rest')` is a visual phase selector and does not infer task progress. `animate(seconds, { paused, reducedMotion })` animates only the flame. Call `dispose()` when removing the outpost.

`createMemorialGarden({ memorials, readiness, capacity })` accepts an ordered list of `{ id, iteration, texture }`. A `texture` is an optional caller-created CanvasTexture. Its art is shown on an upright rounded tablet. Existing entries supplied during construction are placed in their stable archive positions and never replay their rise. Use `setMemorials(list, { initial: true })` when the archive loads asynchronously; these entries also appear settled. Later entries rise only after all four IDs `dispenser`, `computer`, `campfire`, and `agents` are ready. All marks are hidden while any readiness gate is false; restoring gates shows settled archive entries and resumes new entries mid-rise. The component deduplicates by stable ID. Placement follows a fixed index-based spiral; IDs and archive order should therefore remain stable. `overflow` reports distinct rejected IDs in the most recent ordered list, so repeated polling does not inflate it. `update(deltaSeconds)` advances the rise by translating tablets from underground to their ground position; invalid, negative, and very large deltas are ignored or bounded. Paused or reduced-motion flags stop it (reduced motion settles new marks immediately).

Both components create no model, image, or orchestration requests. Memorial metadata is stored in `userData` for selection. The garden disposes its own geometry and materials, but never disposes injected textures; the caller remains their owner. The outpost's `dispose()` releases its shared materials and geometries.
