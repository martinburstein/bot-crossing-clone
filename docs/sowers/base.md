# Procedural mission base

`sowers/base.js` exports `createMissionBase({seed='Sowers', progress=0, kind='habitat', color=0xf5823a})`. It returns an original Three.js group, local ground at Y=0, entry face toward +Z, within an 8 × 8 footprint and height 5. Supported kinds include habitat, power/solar, relay/command/observatory, and lab/research. Seeded roof variants and service-pod placement make repeatable variations. White pressure shells, orange rails, charcoal decks, amber windows, solar cells, a dish and service pod are procedural geometry; no commercial model or downloaded assets are used.

`group.userData.setProgress(fraction)` reveals the fixed parts in foundation, frame, shell, systems, beacon order. Existing pieces never move or change layout with progress. Partial construction includes temporary orange gantries and diagonal braces. `animate(elapsed, delta)` gently pulses the beacon/window material. `height` and `footprint` are available for placement. A caller may animate the fraction to reveal assembly, but must label such an animation as presentation when it does not measure task completion.

`observedConstruction(thread)` in `progress.mjs` keeps evidence separate from assembly. A finite `constructionProgress` in [0,1] is explicitly reported progress. A nonempty `plan.steps` provides a declared denominator and counts only `status: 'completed'`; plans can change, so this is a step ratio, not guaranteed effort completion. Without either source, the result's fraction is null. Active canonical milestones count earned checkpoints without claiming a denominator. Explicitly rejected, pending, unaccepted or retracted milestones are excluded; canonical milestone records without acceptance metadata are treated as already accepted by their source. The renderer can show one additional completed structure per checkpoint with a checkpoint-count label. A scaffold baseline for an unknown task must retain the 'Awaiting measured checkpoints' or 'remaining work unknown' label.

The existing server API reads harness thread metadata and canonical Swarm milestones. `src/game/colony.js` currently targets complete normal buildings and separately computes log transcript size for cards. Transcript bytes, token usage, elapsed time, running/idle state and a closed or cancelled run do not establish completion; the helper deliberately ignores all of them. It does not mutate protocol state or write a second progress store.

Validation: `node --test test/sowers-progress.test.mjs` checks unknown/explicit/plan/checkpoint evidence, excluded milestones, ordered monotonic reveals, deterministic seeded placement, unchanged component transforms during progress, scaffold removal and geometry bounds over 16 seeded kind combinations. These sampled geometry checks do not prove collision-free placement between separate bases.
